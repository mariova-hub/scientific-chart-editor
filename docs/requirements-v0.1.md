# Scientific Chart Editor v0.1 要件定義

## 1. 文書の位置付け

本書は Scientific Chart Editor v0.1 の機能範囲、完成条件、非目標、および最初の実装縦切りを定める実装前契約である。内部構造は `architecture-v0.1.md`、編集用プロジェクトファイルは `project-format-v0.1.md` を正とする。

本書における「必須」は v0.1 のリリース条件を意味する。「将来拡張」は v0.1 でUIや動作を提供することを意味しない。

## 2. 目的と製品境界

Scientific Chart Editor は、Chromebook / Chrome 上で動作する科学実験・研究向けのグラフ編集Webアプリである。Google Sheets等で解析・計算済みの表データを受け取り、Excelデスクトップ版のグラフ編集に慣れた利用者が違和感なく、科学グラフに必要な詳細設定を行えることを目指す。

主な価値は次のとおりである。

- 表データのコピー＆ペーストからグラフ作成までを短い操作で行える。
- 個々のデータ点に対応する誤差値、軸、系列、近似曲線を明示的に設定できる。
- 編集可能な独自プロジェクトとして保存し、後日、同一の編集状態から再開できる。
- レポートや研究資料に利用できるSVG、および一般的な画像用途のPNGを出力できる。

対象者を高校生向けに限定せず、操作を過度に単純化しない。一方で、Excel自体のクローンは作らず、表計算ではなく科学グラフの作成・編集に製品境界を置く。

## 3. v0.1の機能要件

### 3.1 データ入力と保持

- Google Sheets等の表計算アプリから、タブ区切り・改行区切りの表データをクリップボード経由で貼り付けられること。
- 貼り付けた値を行・列からなる表として保持し、列見出しとセルの位置関係を失わないこと。
- セルは少なくとも数値、文字列、空セルを区別して保持できること。具体的な保存表現は `project-format-v0.1.md` に従う。
- 利用者が各系列のX値とY値に用いる列全体、またはその列内の連続範囲を指定できること。
- 指定済みのX値とY値の割当を入れ替えられること。
- 1つのグラフに複数系列を追加、選択、編集、削除できること。
- X値、Y値、誤差値として選択した範囲の長さや型が不適切な場合、描画前に理由を示し、無言で値を切り捨てないこと。
- 空セルまたは数値でないセルを含むデータの扱いは一貫して検証し、描画不能な点は利用者に識別可能な形で通知すること。具体的な許容規則は実装開始前に確定する。

v0.1は表データの受け入れとグラフへの割当に必要な操作を提供するが、汎用表計算機能は提供しない。

### 3.2 グラフ種類

次のグラフ種類を作成・再編集できること。

- 散布図
- 折れ線グラフ
- 縦棒グラフ
- 横棒グラフ

グラフ種類はScientific Chart Editorの意味モデルとして保持する。描画ライブラリ固有の種類名を保存形式やUIの正規値にしない。

### 3.3 エラーバー

- 系列ごとにX方向とY方向のエラーバーを独立して有効・無効にできること。
- 各データ点に異なる誤差値を割り当てられること。
- 誤差値の入力元として、元データ内の任意列またはその列内の連続範囲を指定できること。
- v0.1では、各点の正方向と負方向に同じ絶対誤差値を使う正負対称エラーバーを提供すること。
- 誤差値は0以上の有限数として検証し、系列の対象点数と一致しない場合はエラーとすること。
- XエラーバーとYエラーバーの設定および元データ参照をプロジェクトに保存し、読み込み後に復元すること。

将来の非対称エラーバーで正方向・負方向の値を別々に保持できるよう、内部モデルと保存形式では対称性を明示する。v0.1で非対称値の入力UIや描画は提供しない。

### 3.4 軸

X軸とY軸について、それぞれ次を設定できること。

- 軸タイトル
- 最小値（自動または有限数）
- 最大値（自動または有限数）
- 主目盛間隔（自動または正の有限数）
- 補助目盛間隔（なし、自動、または正の有限数）
- 目盛方向
- 線形軸または対数軸
- 軸反転
- 主グリッド線と補助グリッド線の表示

入力値は相互整合性を検証する。例として、通常方向の軸では明示した最小値が最大値未満でなければならず、対数軸では表示範囲および描画対象値が正でなければならない。

数値表示形式はv0.1で少なくとも自動表示を提供し、内部モデルでは将来、固定小数、指数表記、有効数字等を追加可能な構造にする。

### 3.5 系列書式

系列ごとに次を設定し、保存・復元できること。

- 色
- 線幅
- 線種
- マーカー種類
- マーカーサイズ
- 棒グラフの基本書式

「棒グラフの基本書式」は少なくとも塗り色、枠線色、枠線幅を含む。棒の間隔、系列の重なり等をv0.1に含めるかは実装開始前に確定する。

### 3.6 グラフ全体とレイアウト

- グラフタイトルの文字列と表示・非表示を設定できること。
- 凡例の表示・非表示と基本位置を設定できること。
- グラフの幅と高さをピクセル単位で設定できること。
- グラフ領域をドラッグしてリサイズでき、その結果が幅・高さの正規状態に反映されること。
- タイトル、凡例、グラフサイズを保存し、読み込み後に復元すること。

リサイズ中の一時値ではなく、操作確定後のChart Modelを保存対象とする。

### 3.7 近似曲線・回帰

系列に対して次の回帰種類を設定できること。

- 線形
- 多項式
- 指数
- 対数
- べき乗

さらに次を提供すること。

- グラフ上への回帰式表示の切り替え
- グラフ上へのR²表示の切り替え
- 多項式の次数指定。許容範囲の上限は実装開始前に確定する。
- 各方式の定義域、必要点数、計算失敗を検証し、計算不能を誤った曲線として描画しないこと。

回帰計算は描画ライブラリに依存しないRegression Engineが行い、設定はTrendline Modelとして保持する。回帰係数、曲線上のサンプル点、表示文字列は元データと設定から再計算可能な派生値とする。

### 3.8 保存・読み込み

保存・読み込みはv0.1の必須機能であり、画像出力とは別機能である。

- 編集状態を `*.scientific-chart.json` のScientific Chart Editor独自プロジェクトファイルとしてローカルに保存できること。
- 保存形式にschema versionを持たせ、Plotlyの`layout`、`trace`、`Data[]`等を正規保存状態にしないこと。
- ローカルファイルからプロジェクトを読み込み、検証後に編集状態へ反映できること。
- 壊れたJSON、未対応version、必須項目欠落、不正な参照、不正な数値を安全に拒否し、現在編集中のプロジェクトを破壊しないこと。
- 保存と読み込みはUIコンポーネントから分離したPersistence層を経由すること。

保存・読み込みの完成条件は次のシナリオが成立することである。

1. データ、系列、エラーバー、軸、近似曲線、書式、グラフサイズを含むプロジェクトを保存する。
2. アプリを閉じる。
3. アプリを再起動する。
4. 保存したプロジェクトファイルを読み込む。
5. 再描画可能な元データと、全ての利用者設定が意味的に同一な状態へ復元される。
6. 復元直後から設定変更、再保存、画像出力を継続できる。

「意味的に同一」はJSONのキー順、空白、生成日時、派生キャッシュが同一という意味ではなく、同じデータ参照、設定、書式、サイズから同じグラフを再生成できることを意味する。

### 3.9 出力

- 現在のグラフをSVGとしてローカルに出力できること。
- 現在のグラフをPNGとしてローカルに出力できること。
- SVGは文字、線、マーカー、エラーバー、近似曲線を含むベクター出力を基本とし、科学レポート等で利用可能な品質を優先すること。
- 出力画像にはデータグリッド、選択枠、右側ペイン等の編集UIを含めないこと。
- 出力結果は画面上の確定済みChart Modelと意味的に一致すること。

## 4. UI要件

基本画面はExcelライクな次の3領域で構成する。

- データ領域
- グラフ領域
- 右側の書式設定ペイン

グラフ内または関連UIで選択した対象に応じ、右側ペインの編集対象を少なくとも次の単位で切り替えられる構造とする。

- グラフ
- X軸
- Y軸
- 系列
- エラーバー
- 近似曲線
- 凡例
- タイトル

Phase 0-BではUIを実装しない。詳細な画面寸法、キーボード操作、ペイン内の項目配置は後続設計で決定する。

## 5. 動作環境と非機能要件

### 5.1 対象環境

最低限、次の環境を対象とする。

- Chromebook上のGoogle Chrome
- Google Chrome
- Windows上のGoogle Chrome

具体的なChromeの最低versionとサポート期間は実装開始前に確定する。

### 5.2 クライアントサイド完結

- 表データ、Chart Model、回帰計算、保存ファイル生成、読み込み、SVG / PNG出力は原則としてブラウザ内で完結させる。
- v0.1はクラウドアカウント、サーバー保存、常設バックエンドを要求しない。
- 利用者が明示的に保存または出力しない限り、プロジェクト内容を外部サービスへ送信しない設計とする。

### 5.3 品質

- 同じ有効なChart Modelからは、ブラウザ再起動をまたいでも意味的に同じ描画入力を生成できること。
- 入力検証、回帰、変換、保存形式は描画ライブラリから独立してテスト可能な境界を持つこと。
- 想定データ規模、ファイルサイズ上限、描画応答時間の具体値は実装開始前に性能予算として確定する。
- マウス操作を主経路としつつ、主要操作のキーボード利用とアクセシビリティ方針を実装開始前に確定する。

## 6. v0.1の非目標

次はv0.1の対象外とする。

- Excel完全互換
- セル関数
- 条件付き書式
- セル結合
- ピボットテーブル
- マクロ
- VBA
- 高度な統計検定
- 任意Pythonコード実行
- 任意関数による非線形フィッティング
- クラウドアカウント
- サーバー側データ保存
- Excelファイル完全互換
- 複数グラフの自由レイアウト

これらを将来追加する可能性は否定しないが、v0.1のモデルに未使用の複雑性を持ち込まない。第2軸、非対称エラーバー、複数近似曲線、注釈、テキストボックス等については、既存ファイルを不必要に破壊しない拡張点のみ確保する。

## 7. 最初の実装縦切り

v0.1全体へ横展開する前に、次の経路を端から端まで実装する。

```text
Google Sheetsから表を貼る
↓
表データとして保持
↓
X列・Y列指定
↓
散布図生成
↓
Yエラーバーを別列指定
↓
X/Y軸の最小・最大・主目盛変更
↓
グラフサイズ変更
↓
プロジェクト保存
↓
アプリを再起動
↓
プロジェクト読込
↓
同一編集状態を復元
↓
SVG出力
```

この縦切りの完了条件は、単一系列の散布図について、貼り付けた表、X/Y割当、点ごとの対称Yエラーバー、X/Y軸の最小・最大・主目盛、幅・高さが保存前後で意味的に一致し、復元後のSVGにも反映されることである。確認では実際にアプリを終了・再起動し、メモリ内状態だけに依存していないことを検証する。

縦切りが成立するまで、棒グラフ、複数系列、Xエラーバー、PNG、詳細書式、高度な回帰方式等への横展開を行わない。ただし縦切り時点から、Chart Model、Renderer Adapter、Persistence、Regression Engineの責務境界は本設計に従う。

## 8. v0.1リリース判定

v0.1は次を全て満たした時点で完成とする。

- 3章の必須機能が対象ブラウザで利用できる。
- 保存・再起動・読み込み・編集再開の完成シナリオが成立する。
- Plotly固有状態をプロジェクト形式へ保存していない。
- SVG / PNGが確定済み編集状態と一致する。
- 有効・無効なデータ、プロジェクトファイル、回帰定義域に対する検証がある。
- 最初の実装縦切りを先に完了し、その境界を維持したまま残機能へ展開している。

## 9. 実装開始前の未確定事項

次は製品境界を変えないが、実装と受け入れ基準に影響するため着手前に決定する。

- 列見出しの自動判定規則と、見出しなしデータの扱い
- 空セル・文字列・不正数値を含む点の欠損値方針
- 貼り付け可能な行列数、プロジェクトファイルサイズ、SVG / PNG寸法の上限
- 対象Chromeの最低versionと更新方針
- 多項式回帰の最大次数と各回帰方式の数値精度基準
- 対数の底、および回帰式とR²の表示桁・表記規則
- PNGの既定解像度、倍率、背景透過の扱い
- 色の入力方式、利用可能な線種・マーカー種類の確定一覧
- 棒の間隔・系列重なりをv0.1の「基本書式」に含める範囲
- Undo / Redoをv0.1リリース機能に含めるか。アーキテクチャは後付け可能にする。
- 主要操作のキーボード対応、フォーカス移動、アクセシビリティの受け入れ基準

## 10. Phase 1で確定した縦切り規則

Phase 1の実装では、最初の縦切りに限り次を確定した。

- TSVの1行目は常に列見出しとし、自動推定しない。
- データは最大256列・10,000行、プロジェクトファイルは最大5 MiBとする。
- 空セルと空白だけのセルは`null`とする。前後空白を除いたセル全体が10進数または指数表記の有限数に一致する場合だけ`number`とし、それ以外は元の`string`を保持する。
- データ途中の空行は全セル`null`の行として保持し、クリップボード末尾の空行だけを除去する。
- XまたはYが数値でない行は描画対象から除外するが、元データは変更しない。
- Y Error列が指定されている場合、描画対象となるX/Y行のY Errorに`null`、非`number`、非有限値、負値が1件でもあれば、その系列のエラーバー表示全体を無効化し、該当件数をUIに警告する。散布点と元のセル値は維持する。数値の0は有効な誤差値として扱う。
- Phase 1のグラフ寸法は幅360〜1,600px、高さ300〜1,200pxとする。
- Phase 1は単一dataset・単一散布図系列・対称Yエラーバーだけを編集対象とする。

これらはPhase 1のScope Guardであり、v0.1全体の機能を削除するものではない。

## 11. Phase 2で確定した書式編集規則

Phase 2では単一散布図の書式編集基盤として次を確定した。

- 書式設定対象はグラフ、X軸、Y軸、データ系列、Y誤差範囲、凡例、グラフタイトルを明示的に切り替える。選択状態は一時的UI状態であり、プロジェクトには保存しない。
- 軸は線形／対数、反転、Autoまたは明示範囲、主・補助目盛間隔、主・補助目盛表示、目盛方向、軸線、主・補助グリッド、軸ラベル書式を編集できる。
- 対数軸への変更は、明示範囲または描画値（表示されるY誤差範囲を含む）が0以下になる場合に拒否し、該当件数を示す。対数軸中に不適合データへ変更する操作も拒否する。
- 系列はマーカーの表示、形、サイズ、塗り色、枠線色、枠線幅、および将来の折れ線と共用する線の表示、色、幅、線種を編集できる。
- Y誤差範囲は表示、色、線幅、キャップサイズを編集できる。ただしPhase 1の無効誤差値による系列全体非表示を優先し、書式で回避できない。
- グラフ背景、プロット領域背景、タイトルの表示・文字・フォント・サイズ・色・太字、凡例の表示と上下左右位置を編集できる。
- 数値入力は編集途中のdraftと確定Model値を分離する。テキスト、チェック、色、選択値は変更時に、数値はblurまたはEnterで確定し、毎回の「適用」操作を要求しない。
- グラフ右下のハンドルでサイズを変更できる。ドラッグ中は妥当な範囲へclampしたUI previewとし、pointer操作の確定時に整数pxをChart Modelへ1回反映する。
- 色の正規形は`#RRGGBB`とし、明示された不正色は読み込み時に拒否する。

Phase 2でも棒・折れ線グラフ、複数系列、回帰、Xエラーバー等へは横展開しない。

## 12. Phase 3Aで確定した棒グラフ・Data Grid規則

- 現在のグラフ種類は`scatter`または`bar`とし、縦棒／横棒は別種類にせず`bar.orientation`（`vertical` / `horizontal`）で表す。
- 棒系列は散布図のX/Yとは別にCategory / Value / Errorという意味bindingを持つ。方向変更はbindingを変更せず、縦棒ではCategory→X・Value→Y・Error→Y、横棒ではValue→X・Category→Y・Error→Xへ描画時に対応させる。
- Categoryは有限numberまたはstring、Valueは有限numberを受け入れる。CategoryまたはValueが不正な行は描画対象外とするが元データは保持し、除外件数を表示する。
- Errorが指定された描画対象行では、全値が0以上の有限numberでなければならない。1件でも不正なら全ての棒の誤差範囲を非表示にして件数を警告する。0は有効値であり、不正値を0へ置換しない。
- カテゴリ軸ではmin/max、major/minor interval、linear/log等の数値軸専用設定をUIで提示せず、Rendererにも適用しない。値軸はPhase 2の軸書式を継続利用する。
- 値軸の明示minimumが0以外でも描画と保存を許可するが、比較の見え方が強調される可能性を非ブロッキング警告で示し、値を自動補正しない。
- 棒書式は塗り色、枠線色、枠線幅、不透明度、棒幅、およびグラフ単位の棒間隔を意味値として保存する。
- Data Gridは固定見出し・固定行番号、縦横スクロール、128px以上の基本列幅、13px文字、38px行高を提供する。利用中の列は背景だけでなく`X` / `Y` / `ERR`または`CATEGORY` / `VALUE` / `ERR`ラベルで示す。
- Data Pane幅は320〜720pxでドラッグまたはキーボード調整できるSession Stateとし、プロジェクトには保存しない。グラフ寸法のドラッグリサイズとは別の責務である。

Phase 3Aは単一系列の棒グラフに限定し、複数系列、grouped / stacked bars、回帰、非対称誤差等には横展開しない。

## 13. Phase 3B-1で確定したData Grid Paste規則

- Data Gridはimport結果のpreviewではなく、セルを選択して更新できるeditable gridとする。通常の貼り付け経路は専用textareaではなく、active cell上のブラウザ標準paste eventである。
- active cellは見出し行を含む0-basedの`rowIndex` / `columnIndex`としてSession Stateに保持する。表示上のA1は`0,0`であり、プロジェクトへ保存しない。
- Datasetの第1行相当は列見出しとして扱う。A1やC1への貼り付けは該当`ColumnModel.name`を更新し、C2以降への貼り付けはC1の既存見出しを変更しない。clipboard blockの先頭行を毎回見出しとは解釈しない。
- Clipboard TSVは各セルを`number | string | null`へparseした矩形値として扱い、active cellを左上として該当範囲だけを更新する。短い行は矩形内で`null`へ補完する。
- 初回A1貼り付け、既存セル上書き、別列追加、行追加は同じRectangular Paste contractを使用する。通常PasteでDataset全体を置換しない。
- 貼り付け先が現在範囲外なら必要な行・列だけを追加する。既存の最大256列・10,000データ行を超える場合は、状態を一部変更せず操作全体を拒否する。
- 部分更新ではdataset、既存column、既存rowのstable IDを維持し、新規行列だけIDを生成する。したがって、参照列が存在する限り散布図・棒グラフのbindingを維持する。
- 1回のPasteは候補Datasetを含む単一`paste-range` Reducer actionとして確定する。セルごとのactionへ分割せず、将来1操作単位のUndo / Redoへ接続可能にする。
- セルクリックを必須経路とし、Arrow、Tab、Enterによるactive cell移動も提供する。複数セル選択、copy、cut、delete、数式、sort、filterはPhase 3B-1に含めない。

Phase 1の「TSV blockの1行目を常にheaderとしてDataset全体を作る」規則は、旧`parseTsv` importerと過去テストの互換契約としてのみ残す。Phase 3B-1以降の通常Grid Pasteでは、本節の座標ベース規則を優先する。

## 14. Phase 3B-2で確定した数値軸範囲規則

- 散布図ではX軸・Y軸を独立した数値軸とし、それぞれ最小値、最大値、主目盛間隔、補助目盛間隔をAutoまたは固定値として編集できる。
- 縦棒ではY軸、横棒ではX軸だけを数値値軸として同じ編集UIへ接続する。縦棒のX軸・横棒のY軸はカテゴリ軸であり、数値範囲・目盛り間隔・対数設定を提示または描画へ適用しない。
- Autoは空欄の副作用だけにせず、各項目の「自動に戻す」操作として明示する。UIは現在値が「自動」か「固定」かを表示する。
- 数値draftはblurまたはEnterで確定する。有限数、`minimum < maximum`、主・補助目盛間隔が0より大きいことを候補Projectで検証し、不正なら直前のChart Modelを維持して具体的な理由を表示する。値をclampまたは別値へ補正しない。
- 対数軸の固定minimum / maximumは0より大きくなければならない。既存の描画データ・誤差下端の対数validationも引き続き適用する。
- 棒グラフ値軸の固定minimumが0以外の場合は設定を受理し、0 baselineの非ブロッキング警告を表示する。

## 15. Phase 3B-3で確定したセル直接編集規則

- Active Cellとは別に、編集中セルと文字列draftをSession Stateとして保持する。セル編集の途中値、composition状態、エラー表示はProjectへ保存しない。
- ダブルクリック、Active CellでのEnterまたはF2は現在値をdraftにした編集を開始する。非編集中の通常文字入力は既存値を連結せず、その入力文字から置換編集を開始する。
- 編集中のEnterは確定して下（Shift+Enterは上）、Tabは確定して右（Shift+Tabは左）へ移動する。EscapeはDatasetを変更せず編集を取り消し、blurは現在draftを安全に確定する。編集中のArrow / Backspaceはテキストeditor本来の操作へ渡す。
- IME composition中またはDOMがIME処理中を示す`keyCode: 229`のEnterは、セル編集の確定として扱わない。日本語変換の確定後に押された通常のEnterだけがセルを確定する。
- 編集確定はPasteと同じ`parseCell`規則を使用する。有限な10進数・指数表記はnumber、空文字または空白だけはnull、NaN / Infinityを含むその他はstringである。
- 見出し編集は`ColumnModel.name`だけを変更し、空見出しは空stringとして保持する。選択UIは列記号を含む「A列（見出しなし）」等のfallbackを表示し、データへ補完名を書き戻さない。
- 非編集中のDelete / Backspaceは、データセルをnull、見出しを空stringへ変更する。行・列・stable IDは削除しない。編集モード中のBackspaceは文字削除である。
- 直接編集・消去は対象セル値だけを変更し、既存dataset / row / column IDとcolumn ID参照のbindingを維持する。値に応じた描画除外・誤差値警告は確定後に再計算する。
- 1セルの編集確定は単一`edit-cell` action、1セルの消去は単一`clear-cell` actionでProject Reducerへ渡し、UIからModelを直接変更しない。将来のUndo / Redoでは各actionを1操作として記録できる。
- 非編集中のCtrl / Cmd + Vは従来の矩形Grid Pasteを継続する。編集中のPasteはセル内editorの通常文字入力として扱い、Grid Pasteとの二重適用を禁止する。

Phase 3B-3では範囲選択、copy、cut、複数セル消去、数式、行列操作、Undo / Redoへは横展開しない。

## 16. Phase 3B-4で確定した行／列データ解釈規則

- Chart Modelは`dataOrientation: columns | rows`を持つ。これは棒グラフの`vertical | horizontal`、散布図のX/Y binding、Datasetの物理配置とは独立したScientific Chart Editorの意味設定である。
- `columns`は従来どおりCategory / Value / Errorの列bindingを同一行で対応させる。Phase 1〜3B-3ファイルはfield欠落時に`columns`へdefault hydrationする。
- Phase 3B-4の`rows`は単一棒系列で利用できる。カテゴリは明示した開始・終了column ID間の列見出し、値と誤差はstable row IDで指定した行を同じcolumn位置で読む。
- rows modeはdataset ID、カテゴリ開始・終了column ID、value row ID、任意error row ID、任意label column IDを保持する。配列indexやA/B等の列記号を永続参照にしない。
- 行選択UIはlabel columnのセルを使い、例えば`2行目（平均）`と表示する。既定label候補は先頭列だが、候補はstable column IDとして保持し、任意列指定へ発展可能にする。
- カテゴリ範囲外の列は描画対象にしない。Valueが有限numberでない位置だけを除外し、後続Category / Errorを詰めない。描画対象位置のErrorにnull、非number、非有限値、負値が1件でもあれば棒を維持して系列全体の誤差範囲を非表示にし、件数を警告する。0は有効である。
- 行／列切替はDatasetを転置・変更しない。columns bindingとrows bindingを別々に保持し、切替時に既存の明示bindingは再利用できるが、一方から他方を推測生成しない。初回rows切替では必要項目を未設定として再指定を促す。
- rows modeでも棒の縦／横は独立して変更できる。同じrow bindingを縦棒ではCategory→X・Value→Y・Error→Y、横棒ではValue→X・Category→Y・Error→XへRenderer Adapterが変換する。
- rows modeで参照中のセル、列見出し、value/error rowを直接編集または矩形Pasteしてもstable ID bindingを維持し、描画・除外・誤差検証を即時再計算する。
- Scatter rows modeはPhase 3B-4では未対応とし、UIで選択不能にする。rows modeからscatterへ変更する場合はデータ方向を安全な`columns`へ戻し、保存済みrow bindingは将来再利用できるよう保持する。

Phase 3B-4ではData Grid自体の転置、複数Value row、複数系列、grouped / stacked barsへは横展開しない。

## 17. Phase 3B-5で確定したrows mode表示用語

- 永続Modelのcategory start / end column ID、value / error row ID、label column IDと、ユーザー向けの操作用語を分離する。rows modeで提示する意味は「カテゴリ範囲」「値」「誤差範囲」である。
- カテゴリは1つの意味的な「カテゴリ範囲」として扱い、表計算形式の`B1:F1`を表示する。Phase 3B-5では同じfield内の「開始」「終了」selectorで指定し、将来のData Grid範囲選択へ置換可能にする。
- 行ラベル列は通常UIへ表示しない。有効な保存済みlabel column ID、先頭列、行番号の順で表示名を自動解決し、string / numberのラベルがあれば`2行目（平均）`、なければ`2行目`と表示する。
- 誤差を使用しない状態は「誤差範囲: なし」として明示し、不正参照や無効な誤差値とは区別する。
- columns modeの単一棒系列も「カテゴリ」「値」「誤差範囲」とし、rows modeとの意味対応を保つ。Data OrientationのUI名は引き続き「データ系列の方向: 列／行」とする。
- `CATEGORY` / `VALUE` / `ERR`のGrid badge、stable ID binding、Dataset非転置、Error validationはUI用語変更によって変更しない。

Phase 3B-5ではData Grid範囲選択、row label列の詳細設定、Scatter rows mode、複数系列へは横展開しない。

## 18. Phase 3Cで確定した軸・目盛・プロット領域規則

- 軸選択時の書式設定は「軸のオプション」「目盛」「ラベル」「軸線」「グリッド線」「軸タイトル」に分け、内部field名ではなく一般的なグラフ用語を表示する。
- 数値軸は範囲、主・補助目盛間隔、linear / log、反転に加え、主・補助目盛の表示、方向、独立した長さ、共通線幅を編集できる。カテゴリ軸にはnumeric-only設定を提示または適用しない。
- 目盛ラベルは表示、font family、サイズ、色、太字、角度を持つ。数値軸の表示形式は自動、整数、小数、指数表記とし、小数・指数表記は0〜10桁の小数点以下桁数を保持する。
- 主・補助グリッド線はそれぞれ表示、色、太さ、実線／破線／点線を独立設定する。軸タイトルも表示、文字列、font family、サイズ、色、太字をX/Y軸ごとに保持する。
- プロット領域はグラフ背景と別の背景色、枠線の表示・色・太さ、Autoまたは手動の上下左右余白を持つ。手動余白はグラフ寸法内に100px以上のプロット幅・高さを残さなければならない。
- font size、線幅、目盛長さはModel内部ではrenderer-neutralな数値として保持し、UIでは`pt相当`と示す。グラフ寸法とプロット余白はpxを維持する。
- Plotlyに真の交差目盛がないため、`cross`は旧ファイル互換enumとして保持するが新規UIから外す。旧値は読み込み・保存でき、UIで互換状態と制約を明示する。
- 書式の数値入力はdraftからblur / Enterで確定し、有限値、許容範囲、整数条件、手動余白整合を候補Projectで検証する。不正候補はChart Modelへ反映せず、値を黙ってclampしない。
- Phase 3Cの全意味書式は独自Project JSONへ保存し、同じRenderer Adapter経路を使う画面描画とSVG出力の双方へ反映する。Selection、draft、警告は保存しない。

Phase 3Cは軸・目盛・プロット領域の書式完成に限定し、複数系列、回帰、データラベル、PNG、テーマへは横展開しない。

## 19. Phase 3Dで確定した画像出力・軸文字配置規則

- 画像出力はPNG / SVGを明示選択できる。PNGはChart Modelの`widthPx` / `heightPx`を論理サイズとし、標準・2×・3×の一時的なexport scaleで実ピクセル寸法を変更する。出力によってChart Modelの寸法を変更しない。
- PNG背景は「現在の背景」または「透明」を選べる。透明指定はexport用Figureのpaper / plot背景にだけ適用し、保存済みグラフ背景を変更しない。SVGは従来どおり現在の背景を使用する。
- PNG scale、PNG背景、選択中の出力形式はSession / Export OptionでありProjectへ保存しない。出力ファイル名はOSで安全な`scientific-chart.png` / `scientific-chart.svg`とする。
- 目盛ラベルはPhase 3C書式に加え、軸の外側／内側と、軸からの距離をX/Y軸ごとに保持する。実際の描画と一致する`outside | inside`だけをUIへ提示する。
- 軸タイトルは目盛ラベルとは別Modelであり、表示・文字・font書式に加え、目盛ラベルからの距離をX/Y軸ごとに保持する。
- ラベル距離とタイトル距離は0〜100pxの有限numberとする。負値や範囲外値は候補Chart Modelへ反映せず理由を表示し、黙って補正しない。軸方向への平行シフトと軸タイトルの任意2次元ドラッグはPhase 3Dの対象外である。
- Auto MarginではRendererの自動余白を有効にして距離増加による文字切れを抑える。Manual Marginでは利用者の保存値を優先し、距離設定のためにmarginを勝手に変更しない。
- 目盛ラベル位置・距離と軸タイトル距離は画面、PNG、SVGへ同じAdapter mappingで反映し、保存・再読込後に復元する。

Phase 3DはPNG出力と軸文字配置の仕上げに限定し、JPEG / PDF、注釈、データラベル、複数系列、回帰へは横展開しない。

## 20. Phase 3D-1で確定した棒グラフの要素間隔規則

- 1系列棒グラフの密度を調整する主設定は、ExcelのGap Widthに相当する「要素の間隔」とする。ユーザーUIは0〜500%で表示し、内部のPlotly `bargap`やtrace `width`を表示しない。
- 意味値は概念的に`間隔 ÷ 棒幅 × 100`である。0%は棒同士が接し、50%は間隔が棒幅の約半分、100%は同程度、200%は約2倍、500%は非常に細い棒と広い間隔になる。
- 同じpercentageは縦棒・横棒、画面表示、PNG 1× / 2× / 3× / 透明、SVG、異なるChart width / heightで同じ意味を維持する。
- 要素間隔の変更はCategory値・順序、tick、grid、軸、Error Bar配列を変更しない。Error Barは各棒の中央へRendererが追従する。
- 数値draftはblur / Enterで確定し、0〜500の有限numberだけを受理する。不正候補は直前のChart Modelを維持し、理由を表示する。値をサイレント補正しない。
- 通常UIから旧「棒の幅」「棒の間隔」の独立入力を撤去し、単一の「要素の間隔 (%)」へ統合する。複数系列の重なり・grouped / stacked barは対象外である。

## 21. Phase 3D-3で確定した軸設定UI用語

- 数値軸のユーザー向け設定は「範囲（最小値・最大値）」と「目盛り間隔（主目盛間隔・補助目盛間隔）」に分けて表示する。
- Auto／固定、入力確定、validationの意味契約は変更しない。カテゴリ軸には範囲・目盛り間隔を表示しない。
- `minimum`、`maximum`、`majorInterval`、`minorInterval`等の内部Model名をユーザー向けラベルへ露出させない。
